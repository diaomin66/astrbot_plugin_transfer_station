# 抽奖与补偿系统

抽奖、补偿与新人礼是三个独立业务系统：

- 新人礼：`gifts.db`
- 抽奖：`lottery.db`
- 补偿：`compensation.db`

两套活动系统只共享 New API 客户端，不读取或修改新人礼的永久用户库、资格、库存或领取记录。

## 1. New API 配置

| 配置项 | 说明 |
| --- | --- |
| `newapi_base_url` | New API 站点根地址，生产环境应使用 HTTPS |
| `newapi_access_token` | 管理员或超管的系统访问令牌，优先使用；不是模型 API Key |
| `newapi_user_id` | 超管用户数字 ID；仅 v0.13.x 等旧版本使用访问令牌时需要，新版留空 |
| `newapi_username` / `newapi_password` | 未配置令牌时的兼容登录方式 |
| `newapi_timeout_seconds` | 单次请求总超时，默认 10 秒，范围 1～120 秒 |
| `newapi_verify_ssl` | 是否验证 TLS 证书，默认开启 |
| `newapi_allow_insecure_http` | 是否允许 HTTP，仅限可信内网测试 |
| `lottery_enabled` | 抽奖总开关 |
| `lottery_enabled_group_ids` | 抽奖群白名单，空列表表示所有 QQ 群 |
| `compensation_enabled` | 补偿总开关 |
| `compensation_enabled_group_ids` | 补偿群白名单，空列表表示所有 QQ 群 |

访问令牌必须具备管理员或超管权限。用户名密码登录遇到 2FA 时会停止连接并要求改用访问令牌。

认证兼容规则：

- 当前 New API 使用 `Authorization: Bearer <系统访问令牌>`。
- New API v0.13.x 等旧版本还要求 `New-Api-User: <超管用户数字 ID>`。
- 使用用户名密码连接旧版时，插件会从登录响应自动读取数字 ID。
- 使用系统访问令牌连接旧版时，需要手动填写 `newapi_user_id`。

群内测试命令：

```text
/newapi 测试
```

调度台也提供“测试连接”按钮。测试流程会读取站点状态、当前身份和管理端用户列表，不会修改任何额度。

密码、令牌和完整接口响应不会写入插件日志。活动 Page 只显示凭据是否配置，不会回显或保存敏感凭据。连接失败时 `{error}` 只显示经过分类和脱敏的原因。

## 2. 额度换算

创建并发布活动时读取 `/api/status`，保存当时的显示单位与换算率快照：

- USD：`金额 × quota_per_unit`
- CNY：`金额 ÷ usd_exchange_rate × quota_per_unit`
- CUSTOM：`金额 ÷ custom_currency_exchange_rate × quota_per_unit`
- TOKENS：输入值直接作为原始 quota

换算使用 `Decimal` 并四舍五入为整数。活动发布或开启后，即使 New API 修改汇率，既定奖励也不会变化。

确认发放时调用：

```json
{
  "action": "add_quota",
  "mode": "add",
  "id": 123,
  "value": 500000
}
```

插件使用 New API 原子增量接口，不会采用“先读余额再覆盖总额度”的方式。

## 3. 抽奖系统

### 管理员指令

```text
/抽奖 创建 <标题>
/抽奖 时间 <开始时间> <开奖时间>
/抽奖 口令 <报名关键词>
/抽奖 描述 <内容>
/抽奖 奖项添加 <奖项名> <人数> <额度>
/抽奖 奖项删除 <序号>
/抽奖 领奖时限 <时长>
/抽奖 发布
/抽奖 状态
/抽奖 参与者 [页码]
/抽奖 提前开奖
/抽奖 取消 [原因]
/抽奖 核查 <流水号> <成功|失败>
/抽奖 帮助
```

全部管理指令要求 AstrBot `ADMIN` 权限。

### 时间规则

- 绝对时间：`YYYY-MM-DDTHH:mm`，按亚洲上海时区解释。
- 相对时间：`now`、`+30m`、`+2h`、`+1d`。
- 新建草稿默认立即开始、1 小时后开奖。
- 默认报名口令为“参与抽奖”。
- 默认领奖期限为 24 小时。
- 发布前必须至少添加一个奖项，且开奖时间晚于开始时间。

报名口令不能与新人礼口令、抽奖领奖和补偿领取命令冲突。

### 报名

用户在活动开放期间准确发送：

```text
@机器人 <报名关键词>
```

同一 QQ 每场只能报名一次。额外文字、未 @机器人或 @其他人均不会触发报名。

### 开奖

开奖前会重新读取当前群成员列表：

- 已退群报名者标记为不符合开奖资格。
- 群成员读取失败时不开奖，调度器稍后重试。
- 使用 `secrets.SystemRandom` 从有效参与者中无重复抽取。
- 按奖项配置顺序分配名额。
- 报名人数不足时所有有效报名者中奖，剩余名额空缺。
- 参与者快照、中奖记录和开奖结果永久保存。
- 重启后不会重新抽取已经开奖的活动。

### 领奖

中奖者发送：

```text
@机器人 抽奖 <New API用户ID>
```

插件查询 New API 用户存在且已启用后，显示活动、奖项、额度、用户 ID 和用户名。用户须在 5 分钟内发送：

```text
@机器人 确认 抽奖
```

或取消：

```text
@机器人 取消 抽奖
```

只有中奖 QQ 本人可以确认。一个中奖资格只能成功发放一次；不同中奖者可以选择同一个有效 New API ID。

领奖逾期后资格作废，不自动补抽。

## 4. 补偿系统

### 管理员指令

```text
/补偿 开启 <每人额度> <持续时间|-> <总金额|-> [标题]
/补偿 状态
/补偿 记录 [页码]
/补偿 关闭 [原因]
/补偿 核查 <流水号> <成功|失败>
/补偿 帮助
```

示例：

```text
/补偿 开启 10 2h 1000 服务异常补偿
/补偿 开启 5 - 500
/补偿 开启 3 1d -
```

持续时间和总金额至少限制一项，`-` 表示不限制。两项同时设置时，任一结束条件先满足即关闭。

### 用户领取

```text
@机器人 补偿 <New API用户ID>
@机器人 确认 补偿
@机器人 取消 补偿
```

单场规则：

- 一个 QQ 只能领取一次。
- 一个 New API ID 只能到账一次。
- 确认状态 5 分钟失效。
- 剩余总金额不足完整一份时自动结束。
- 不发放部分金额，不允许超预算。
- 手动关闭、时间到期或预算耗尽后，未确认申请会取消。
- 活动记录逻辑归档，不物理删除。

下一场补偿使用新活动编号，QQ 和 New API ID 可重新参与。

## 5. 调度台 Page

“抽奖与补偿调度台”提供以下操作：

- 查看系统开关、群范围和 New API 凭据配置状态。
- 修改 New API 根地址、超时、TLS/HTTP 选项。
- 修改抽奖、补偿开关和群白名单。
- 测试 New API 连接、身份和管理权限。
- 创建抽奖草稿，编辑时间、口令、描述和领奖时限。
- 添加、删除奖项，发布、开奖或取消活动。
- 开启或关闭补偿。
- 查看所有当前活动与分页历史。
- 查看中奖、补偿发放记录并处理 `manual_review`。

设置保存使用 revision 乐观锁：

- 页面有未保存内容时，自动刷新不会覆盖表单。
- 如果 AstrBot 设置页或另一个 Page 已经修改配置，旧 revision 保存会被拒绝。
- 刷新后重新确认设置再保存。
- 设置、抽奖草稿和奖项表单提交期间会锁定全部控件，避免重复提交或修改到半途请求。
- 活动操作完成后只有仍处于当前选中状态的活动会刷新详情，切换活动不会被旧请求抢回。

所有活动 ID、New API ID 和原始 quota 均以字符串返回前端，避免 JavaScript 超过 `2^53-1` 后损坏精确值。

## 6. 状态与失败策略

统一状态：

```text
pending_confirmation
processing
paid
failed
manual_review
cancelled
expired
```

确认发放时，SQLite 事务先原子占用中奖资格或补偿预算，再调用 New API：

- 明确 4xx、参数错误或上游明确拒绝：标记 `failed` 并释放占用。
- 超时、断线、5xx、重定向、无法解析的写响应或缺少明确成功标记：标记 `manual_review`。
- `manual_review` 冻结资格和预算，不自动重试。
- 插件重启时遗留 `processing` 在等待安全窗口后转入 `manual_review`。
- 管理员核对 New API 记录后，将流水核查为“成功”完成记账，或核查为“失败”释放占用。

这种策略避免未知结果下重复增加额度。代价是必须人工核对模糊写结果。

## 7. 持久通知

发布、开奖、取消、补偿开启/关闭等群公告先写入数据库 outbox，再通过 OneBot 发送：

- 通知使用 `pending → sending → sent` 租约状态。
- 多插件实例不会重复抢占同一通知。
- OneBot 失败时释放租约，等待后续调度周期重试。
- 取消或关闭活动会废弃同一活动中过时的待发送通知。

## 8. 可配置文案

群内用户回复、管理员回复和错误提示均在 `_conf_schema.json` 中提供对应的 `*_content` 配置。

常用占位符包括：

```text
{activity_id} {title} {amount} {user_id} {username}
{serial} {claim_deadline} {remaining_budget}
```

插件只替换已知占位符，不会把 New API 完整响应或敏感凭据插入群消息。

## 9. 数据与备份

默认数据目录：

```text
data/plugin_data/astrbot_plugin_transfer_station/
├── gifts.db
├── lottery.db
└── compensation.db
```

备份前停止 AstrBot，并复制数据库主文件及可能存在的 `-wal`、`-shm` 文件。恢复时必须使用同一组文件，禁止只替换主数据库而遗漏 WAL。

## 10. 真实验收

上线生产前，应使用测试 New API 实例、测试 QQ 群和测试账号完成：

1. `/newapi 测试` 与 Page 连接测试。
2. 小额度抽奖发布、报名、开奖和确认到账。
3. 小预算补偿开启、领取、预算耗尽和自动关闭。
4. 模拟明确 4xx，确认资格/预算释放。
5. 模拟超时或 5xx，确认进入人工核查且不重复发放。
6. 断开 OneBot 后恢复，确认持久公告继续发送。
