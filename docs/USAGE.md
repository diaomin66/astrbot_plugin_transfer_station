# 使用、部署与故障排查

## 1. 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 插件总开关 |
| `enabled_group_ids` | `[]` | 群号白名单；空列表表示全部群 |
| `welcome_content` | 内置欢迎文案 | 支持 `{claim_phrase}` 占位符 |
| `gift_message_content` | 内置兑换码私聊文案 | 支持 `{code}`、`{claim_phrase}`；缺少 `{code}` 时自动在末尾附加兑换码 |
| `claim_success_content` | 内置发送成功提示 | 成功发送兑换码后的群内回复 |
| `already_claimed_content` | 内置重复领取提示 | 用户已经成功领取时的群内回复 |
| `not_eligible_content` | 内置无资格提示 | 用户没有当前群新人资格时的群内回复 |
| `no_codes_content` | 内置库存不足提示 | 没有可用兑换码时的群内回复 |
| `temporary_chat_failed_content` | 内置会话建立失败提示 | 支持 `{claim_phrase}`，默认引导用户先主动私聊再回群重试 |
| `baseline_pending_content` | 内置基线未完成提示 | 群成员同步失败时停止发放并提示稍后重试 |
| `claim_failed_content` | 内置通用失败提示 | 未识别领取结果的群内回复 |
| `claim_phrase` | `领取新人礼` | 新人必须准确发送的口令 |
| `mention_new_member` | `true` | 欢迎消息是否自动 `@新人` |

配置修改后在 AstrBot WebUI 重载插件。

上述配置覆盖插件发送到 QQ 聊天中的全部文字。管理页面自身的按钮、提示和接口错误不属于机器人聊天文案。

## 2. 兑换码管理

从插件详情打开 **新人礼管理**：

1. 每行粘贴一个兑换码并导入。
2. 空行和重复兑换码会被跳过。
3. 库存中的兑换码默认遮罩，可单独显示或复制。
4. 只能删除尚未发放的库存兑换码。
5. 已发放记录只显示兑换码尾号，完整兑换码不会继续保存。
6. 顶部“数据库人数”和“今日新人”每 10 秒自动刷新；今日按 AstrBot 服务器本地日期计算。

## 3. 领取判定

一次领取必须同时满足：

1. 消息来自启用的 QQ 群。
2. 当前群本次插件运行期间已成功同步完整成员基线。
3. 发送者的 QQ ID 在永久用户库中从未出现过，并在基线完成后触发当前群的 `group_increase` 入群事件。
4. 消息包含对当前机器人的 `@`。
5. 除该 `@` 外只有纯文本领取口令，不包含额外文字、图片或其他成员的 `@`。
6. 该 QQ 号从未在任何群成功领取。
7. 库存至少有一个兑换码。

### 永久防重规则

- 插件每次启动都会调用 `get_group_member_list`，把启用群当前成员写入永久用户库。
- `enabled_group_ids` 为空时，先调用 `get_group_list` 获取机器人所在全部群，再逐群同步成员。
- 旧版本数据库中的资格记录和领取记录会在升级时迁移到永久用户库，并且不再获得新的领取资格。
- 为防止老成员趁插件启动同步期间退群重进，基线尚未完成时出现的入群用户会随当前成员列表写入基线，不补发新人资格。
- 新人首次登记后，即使未领取便退群重进，也只保留原本的一次资格，不会新增资格。
- 领取成功后，领取记录以 QQ ID 全局唯一永久保存。
- 插件没有提供删除永久用户 ID、成员基线或领取记录的 Page/API。
- 群成员同步失败时采用失败关闭：不记录新人、不发送兑换码，并回复 `baseline_pending_content`。

## 4. 数据与备份

数据文件：

```text
data/plugin_data/astrbot_plugin_transfer_station/gifts.db
```

停用或停止 AstrBot 后复制该文件即可备份。恢复时应先停止 AstrBot，再将备份文件放回原路径。

更新到 `v1.2.0` 前应先备份该文件。升级会自动创建永久用户库和群成员基线表，并将旧资格、旧领取记录迁移为永久已知用户。若需要降级到旧版本，应停止 AstrBot 后恢复升级前的数据库备份，而不是只回退插件代码。

数据库包含：

- 永久用户库：QQ号、首次记录群、首次记录时间、来源和可领取群。
- 群成员基线：群号、最后同步时间和同步成员数。
- 新人资格：群号、QQ号、入群时间；仅用于永久用户库中首次登记的新成员。
- 未领取兑换码：完整兑换码和导入时间。
- 领取记录：QQ号、领取群、领取时间、兑换码尾号和摘要。

## 5. QQ 群临时会话要求

- AstrBot 必须使用 `aiocqhttp` 连接 NapCat。
- NapCat 必须能收到群成员增加通知。
- QQ 账号及新人隐私设置必须允许群临时会话。
- 插件调用 `send_private_msg` 时会同时传入 `user_id` 和 `group_id`。

若机器人主动建立临时会话失败：

1. 兑换码立即回滚到库存，不会写入领取记录。
2. 群内发送 `temporary_chat_failed_content` 配置的引导文案。
3. 新人主动私聊机器人发送任意消息，建立可回复的会话上下文。
4. 新人回到原群，重新 `@机器人` 并发送领取口令。
5. 插件再次尝试发送；成功后才删除兑换码并记录领取。

## 6. 常见问题

### 新人入群没有欢迎消息

检查：

- 插件是否启用。
- 群号是否被 `enabled_group_ids` 排除。
- NapCat 日志中是否收到 `notice_type=group_increase`。
- AstrBot 平台是否为 `aiocqhttp`。
- 该 QQ ID 是否已经存在于永久用户库；已记录用户退群重进不会再次欢迎或获得资格。

### 新人提示没有资格

只有群成员基线完成后、永久用户库中从未出现过的 QQ ID 才会记录资格。更新时已经在启用群内、旧版数据库已经记录、在其他启用群出现过或曾成功领取的用户都没有资格。

### 提示成员基线尚未同步

检查 NapCat 登录状态以及 `get_group_list`、`get_group_member_list` 的 OneBot 日志。基线同步失败时插件不会继续发放，以免老成员通过退群重进绕过限制；插件会每 60 秒重试，群内领取或入群事件也会再次触发同步。

### 临时会话发送失败

这通常表示机器人没有成功主动创建初始临时会话，并不一定是新人隐私设置错误。请让新人先主动私聊机器人发送任意消息，再回群重新 `@机器人` 并发送领取口令。发送失败时不会消耗兑换码，也不会占用该用户的一次领取资格。

### 网络超时后的风险

按当前业务策略，任何发送异常都会回滚库存。如果 QQ 端已经送达但 NapCat 响应超时，同一兑换码可能再次被分配。运营人员应结合 NapCat 日志及时核查异常。

### 永久用户库的边界

QQ 群成员接口只能返回当前成员。因此，更新时已经离开所有启用群、旧数据库也从未记录过的历史账号无法自动补录；该账号以后首次重新入群时仍可能被识别为数据库中的新 ID。
